# 005. 两端协同适配现有 WebDAV 配置协议

状态：草案。


## Context

AgenticClash 已有逐配置的 WebDAV 同步，Clash Verge Rev 目前使用 WebDAV ZIP 备份。用户先要求方案并行审查，随后已要求并行实施。本决策仍为提案：Android 基础实现已开始，Service/IPC 范围和桌面前置要求尚未闭合，未建立完整跨端运行保证。

现有 Android 的未知字段解析、单一 state.json、配置提交和条件 MOVE 都需要重新核对。仅在桌面复制接口不能解决这些边界。已有 [ADR 004](commit-projection-session.md) 的完整提交与失败隔离要求继续成立。

## Decision

建议先兼容既有 v1 的配置包与合并规则，两端实现同一契约；Android 也参与状态隔离、远端原包与未知字段保留、可恢复提交和可靠条件发布的改造。具体范围、能力和验收见 [适配方案](../../dev/plans/webdav-cross-client-sync.md)，字节级契约见 [v1 规格](../systems/webdav/protocol-v1.md)，协议常量与模型仍在源码。

共享原始配置资产；本机运行投影、桌面增强和平台设置归本机。Android 应用分流数据由桌面保留，不映射为桌面进程规则。共享身份不直接替换客户端本地 ID。

不改 v1 kind/version 来追求中立命名；不在同目录混写不兼容新格式。不承诺旧客户端保留新增字段。后续确需平台扩展、改变身份或合并算法时另立版本决策与显式迁移，禁止长期双写两个权威源。

## Consequences

- 可以复用已存在的配置包，逐步开放拉取、双向和自动同步。
- Kotlin/Rust 需要相同一致性向量；业务实现各自适配本机事务和生命周期，不引入跨语言同步引擎。
- 同时改两端增加回归范围，但能正面修复原有状态与提交问题。
- Verge 的 Service/IPC 来自第三仓库；HTTP provider 快照播种能力必须在 P0 核验，必要时明确服务端与发布配套范围，不能预设两仓库能闭环。
- 旧客户端和无可靠条件写的服务器限制仍需诚实披露；新端无法替旧端提供未实现的保证。
- 桌面实施须满足目标仓库 issue 规则；当前 Android 基础实现不能代替目标仓库集成与发布验证。

2026-10-28 三路方案审查及修订复核完成，13 项意见在方案层关闭。随后已并行实现 Android 基础与临时 Rust 契约后端。P0 核实 Service/IPC v2.7.6 拒绝 HTTP provider 的 asset 播种；需明确是否扩第三仓库及服务发布范围，本 ADR 保持 proposed。

## Alternatives Considered

- **只改 Verge，完全冻结 Android。** 可做读取工具，但未知字段、提交边界、缓存隔离与端点条件发布问题仍在，无法形成完整双向方案。
- **直接升级跨平台 v2。** 能重新设计身份和扩展，但同时引入迁移、旧设备隔离与双源风险；首期配置资产可用 v1 表达，暂不采用。若审查证明 v1 无法满足首期要求，应在 P0 改决策，而非实现时暗改协议。
- **共用 ZIP 备份。** 两端设备设置和存储结构不同，整包恢复不提供对象级合并与删除语义。
- **共用 Rust 引擎并接 JNI。** 引入跨语言构建与移动生命周期成本，现阶段用协议规格与一致性样本约束两份实现即可。
